# 燃气商城功能盘查

盘查日期：2026-11-10。范围：后端 Java 接口、Vue 用户端和管理端、Android APP、数据库迁移和本地自动化测试。本文按当前代码与接口实现盘查，生产商户、渠道、运营规程和部署基础设施不在本地代码可验证范围内。

## 结论

项目已从静态原型发展为具备真实商品浏览、购物车、结算预览、下单、库存预占、订单管理、优惠券、售后、服务预约和权限管理的系统。仍然不能把当前仓库视作可直接正式运营的完整商城：收款和退款没有真实支付渠道，服务履约没有业务派单效率工具，管理仪表盘仍是静态演示数据，通知/短信没有实际投递，生产部署、隐私合规和移动端真机验收尚未闭环。

用户端点亮的主要业务路径是注册与密码登录、商品搜索详情、收藏历史、购物车、地址、订单预览/创建/查看/取消/确认收货、领券、工单预约/列表/取消、退款申请。后台有员工与角色权限、商品和分类 CRUD、库存操作、订单处理、售后审核、工单派单和优惠券管理等专页。底层还包括数据库迁移、支付回调协议、超时关单、下单补偿和搜索/商品详情缓存。以上“有接口”不表示渠道、运营配置或实际业务流程已经上线验证。

## 可核验的功能与体验问题

|---|---|---|

| P1 | [WorkOrdersView.vue](../frontend/src/views/WorkOrdersView.vue) | 用户端表单向后端提交服务类型枚举 `installation/repair/inspection` 的映射大多正确，但页面本身把详情数据保存在 `selected` 而没有详情交互，未展示工单详情、地址快照和操作进度日志。预约时间和地址流程基本完成，履约追踪仍不足。 |

## 后台和运营缺口

- 后台独立员工/角色管理、商品、分类、库存、订单、优惠券、售后、工单专页已存在；人员管理、权限、库存和主订单流的基础 API 已覆盖，不应再按旧文档误判为全未实现。
- 尚无促销活动管理界面。结算可计算满减和优惠券，但营销规则配置、活动预览、叠加互斥、预算限额及审计需要产品化。
- 热搜词、搜索索引重建、行政区划导入已有后端端点但无对应操作工具；需按权限为内容运营/运维人员补页面或受控运维脚本。
- 管理员日志页面使用通用旧数据列描述；需核实其真实 API DTO 与字段映射，并补充操作对象/结果/时间范围筛选。日志保留、敏感字段脱敏和失败请求审计需要明确策略。
- 订单管理已包括真实查询、详情、状态处理、发货登记和时间线；仍需接入渠道支付状态、退换货/逆向物流、配送异常和通知，避免人工操作后顾客看不到变化。
- 商品页面已有基本 CRUD 和上下架；尚需商品图片上传/媒体管理、图片版权和清晰度校验、完整规格/SKU 库存价格录入、批量导入导出及商品内容发布审核流程。

## 商品、燃气服务与行业特有能力

当前品牌是“燃气商城”，页面包含燃气设备与用气安全内容，但仓库不能证明已经形成从售前适配到安装验收的完整专业业务。建议按实际经营范围决定下列需求：

- 商品建立燃气品类必要的结构化资质和参数，如气源类型、额定热负荷、安装条件、能效与认证、尺寸/配件、保修期、制造商、检验报告及说明书；实现资质过期提醒和停售控制。
- 产品下单前适配检查：地区气源、房屋/烟道/管线条件、现有设备型号、上门勘察结果和施工可达性；将必要提醒和客户确认写入订单快照。
- 服务预约配置区域和时段容量、收费项、上门交通、备件、改约、取消规则、服务队技能资质与签到/签退、服务照片、客户确认及返工投诉闭环。
- 如商业范围包含燃气供应而非仅销售燃气设备，应另行设计开户/实名/地址核验、表具档案、抄表计费、账单/支付、充值、用量告警、停复气和安全事件联动；当前代码未见这些燃气运营模块，不应由“燃气商城”名称推断已实现。
- 商品评价页面显示的平均评分是 `product_review_summary` 聚合；仓库未见可提交评价的顾客 API/界面。补充购买后评价、图片审核、商家回复和违规申诉，或暂时隐藏没有来源的评分展示。

## 建议开发顺序

1. **安全和交易可验证性**：梳理环境密钥、角色权限及用户删除/导出；建立 staging 与真实 MySQL 验收；完成真实支付、退款、回调和对账方案。
2. **交易闭环**：实现 APP/Web 收银台，订单待支付/支付中/成功/失败可恢复，退款状态与渠道一致；补库存与优惠券并发及渠道失败验收。
3. **履约闭环**：工单员工可选派、详情与日志、用户进度页，区域/排班/改约，接物流轨迹和支付/订单/工单通知。
4. **运营管理**：接入真实经营看板；完善客户支持、顾客档案与反馈处理、促销活动配置；补热词/索引/区划维护工具与审计查询。
5. **用户体验及内容**：修正订单状态路由筛选，移除仿电商平台的尺码/PLUS 示例，完成个人资料与账户安全流程，明确评价和图片上传能力，补完善的结算确认步骤。
6. **燃气行业能力**：由运营确认经营范围，再实现设备适配与安全资质、服务队履约及（如适用）燃气计量缴费系统。
7. **发布验收**：完成真机断网恢复、支付回调重放、弱网、账号注销、隐私/崩溃监控、备份恢复及应用商店材料验收。

## 验证范围和局限

盘查期间前端 Vitest：23 个测试文件、88 项测试全部通过。代码审阅覆盖认证、安全配置、商城、购物车、订单、支付、售后、配送、库存、优惠券、工单、用户、统计及管理页面。测试结果只证明现有自动化案例通过；没有使用个人账户执行生产数据写操作，也没有获得真实支付商户、短信供应商、物流商、运维或燃气运营的验收凭据。后端上一轮已有 25 个测试类、报告约 208 项用例，但当前未在本轮重新运行全部 Maven 集成测试。

另有 [module-api-map.md](module-api-map.md)、[frontend/README.md](../frontend/README.md)、[README.md](../README.md) 和若干模块说明包含过时内容，例如声称用户资料/订单 CRUD 未实现，或仍按演示后台状态描述已开发页面。开发排期应以具体 Controller、服务实现与路由调用为准，并将这些文档逐项更新到当前状态。
