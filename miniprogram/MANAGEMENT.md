# 小程序功能与管理说明

入口：“我的 → 员工 / 管理工作台”。管理账号由既有员工系统提供，管理 token 与商城顾客 token 使用独立存储和请求客户端。进入工作台及修改员工/角色后刷新 /admin/auth/me 的授权；服务端继续执行最终权限校验。

## 管理权限

| 模块 | 查看 | 修改 |
| --- | --- | --- |
| 商品 | product:read | product:write |
| 分类 | category:read | category:write |
| 库存 | inventory:read | inventory:write |
| 订单 | order:read | order:write |
| 员工资料 | employee:read | employee:write |
| 员工角色分配 / 重置密码 | employee:read | role:write |
| 用户 | user:read | user:write |
| 角色权限 | role:read | role:write |
| 售后 | aftersale:read | aftersale:write |

查看账号隐藏修改入口，提交时也检查操作权限。员工角色分配使用 /employees/options，不要求额外获得角色目录查看权限。部门、岗位、商品和分类使用当前模块自己的选项接口。库存查询不要求另授予商品查看权限。

## 关键业务行为

- 商品保存默认创建草稿，上架独立操作。管理端填写品牌名称，由现有服务复用或创建品牌。封面和详情图片直接从相册或相机选择上传，支持 JPG、PNG、GIF，单张最多 10MB；详情图最多 20 张，可预览、调整顺序和移除。上传使用独立管理 token 与 `product:write` 权限，已有图片可继续编辑和展示。价格精度、原价关系、图片协议和字段长度在提交前检查；金额保留十进制字符串，大整数编号保持字符串。
- 商品删除前需下架并处理库存；分类删除前需迁移子分类和商品；角色删除前需解除员工关联。后端在事务内执行最终校验，包括最后一个有效管理员和未完结工单处理资格。
- 购物车总额、可用性与结算价格以服务端为准。全选作用于全部分页，并取消当前不可购买商品的选中状态；部分请求失败时重新同步并阻止不可购买商品进入结算。
- 库存建账/入库/出库/盘点使用 requestId。同一表单遇到超时或未知结果后锁定原内容，重试复用请求编号及请求体；返回详情可核对实际库存。关闭表单后重新操作代表新业务动作。
- 结算先调用 /orders/preview，再使用原 orderNo / checkoutToken 创建订单。提交快照在网络请求前存储，结果不明时重新打开页面仍重试原提交。地址、优惠券和备注在待确认期间锁定；服务端明确要求重新结算后才清理原快照。快照与当前顾客会话绑定。
- 员工创建时资料包装在 employee 内，初始密码单独传入。密码至少 12 个字符、最多 72 个 UTF-8 字节。角色与权限分配全量替换，空选择表示明确清空；修改当前账号相关角色后立即刷新授权。
- 待付款订单支持取消；已付款订单通过售后退款。开始履约、发货和售后审核按钮按服务端状态限制。商品库存预占、扣减和取消释放继续由服务端负责。
- 微信退款使用 POST /admin/aftersales/{id}/wechat-refund。后端使用固定 WXAS{售后ID} 查询或提交退款；处理中保持审核通过状态，由员工稍后重试查询。只有后端确认成功才显示完成。其他渠道使用已有凭证登记接口，不能用手工凭证绕过微信退款核验。

## 代码入口

- pages/manage/：按权限展示的管理工作台、筛选、详情、表单及记录分页。
- utils/management.js：模块字段、接口动作、状态规则和字段白名单。
- utils/management-view.js：中文标签、订单明细和操作记录展示。
- utils/admin.js、utils/api.js：分别处理管理端与顾客端请求。
- utils/checkout.js：待确认订单提交快照及恢复规则。
- pages/personal/：个人资料、账户安全和个人记录。
- tests/business-flows.test.cjs：模拟接口下的关键流程回归。

## 验收步骤

1. 使用顾客账号浏览分类与商品，收藏、加购、改变数量、跨页选择，清理不可购买项；确认结算与默认地址、优惠券及备注。
2. 模拟提交后网络断开，重新打开结算页重试，确认后台仅创建一个原订单。切换顾客账号时不可恢复他人的提交快照。
3. 使用只读员工账号确认模块可查看且写入入口隐藏；使用不同模块授权账号验证独立操作权限及授权撤回。
4. 管理商品、分类、员工与角色，核对关联选择、状态筛选及删除约束。修改角色后立即确认当前会话可访问的模块。
5. 库存建账、入库、出库、盘点，核对库存与流水分页；验证出库不超过可用量、盘点不低于锁定量，超时重试不重复记账。
6. 对待付款订单执行取消；对已付款订单开始履约并登记物流；用户端核对状态时间线、收货快照与物流。
7. 提交售后、审核拒绝/通过、撤销待审申请；配置真实商户后验证微信退款处理中与成功状态，并核对订单、支付、库存及处理记录。

## 验证范围与后续接口

本轮自动化使用模拟 wx/API，不会对真实业务数据执行写入。npm run check 检查全部 15 个页面；npm test 覆盖支付、会话隔离、权限、分类树、库存边界与重试、跨页购物车、订单恢复、售后、员工创建及个人资料等流程；npm run check:wechat 使用本机原生编译器编译全部 WXML 与 WXSS。

本轮修改范围为 miniprogram 目录，复用现有 Java 后端和数据库。以下内容仍需后端扩展或实际环境验收，不能将客户端编译通过等同于全部业务上线完成：

- 当前 CartAddRequest 只有 productId / quantity；SKU 可读取和展示，尚无 SKU 编辑接口与按 SKU 购买协议。本轮不展示不能落单的规格选择控件。
- 当前商品媒体通过 URL 维护，缺少上传、媒体存储与文件管理接口。
- 未使用真实员工/顾客账号执行运行中后端的写操作联调，未进行真实 MySQL 并发、微信真机、商户收退款和发布验收。
- 隐私与消息开关保存既有偏好设置，消息实际投递仍依赖服务端通知能力。
- 库存流水为服务端分页；订单和售后操作记录、积分与登录记录沿用服务端返回的数组，在页面分页展示。
