# 角色权限管理

管理端“组织与系统 → 角色权限”支持角色查询、创建、编辑、停用、删除以及按业务模块批量授权。创建时可同时配置权限，角色和权限关系在同一事务提交；任一权限无效则整体回滚。已分配员工的角色不能删除，需先在员工管理调整角色。

角色接口继续使用 `/api/v1/admin/roles`。POST 和 PUT 请求新增可选 `permissionIds` 字段（ID 字符串数组）；省略时保留原接口行为，传空数组表示清空权限。原 `PUT /{id}/permissions` 接口保持兼容。

管理页面查看需要 `role:read`，修改需要 `role:write`。仅查看权限的账号不显示修改操作。内置 admin 角色不可删除、停用或修改权限。多个启用角色的权限取并集；后端每次请求从数据库加载当前授权，已有 token 不会保留被撤销的权限。

导航与路由使用 `/api/v1/admin/auth/me` 返回的权限，进入管理页面时刷新。无统计权限时默认跳到首个获授权模块；无可用模块时显示授权提示。工单处理账号可进入工单模块查看自己的任务。前端控制仅用于交互，最终授权仍由后端执行。

沿用员工管理的有效管理员保护及工单约束：未完结工单的处理人员不能因角色停用或撤权失去处理资格。优惠券、日志、系统配置沿用现有 `operation:*` 权限，不变更其他业务模块权限标识。无需新增数据库迁移。
