# 购物车模块优化

## 2026-11-17：修复微信数组更新导致商品消失

根据微信 3.18.0 的实际报错 `this.data.cart.items.concat is not a function`，进一步定位到前端数组更新路径错误。此前使用 `cart.items.0.quantity`、`cart.items.0.image`，微信更新后可能把商品数组变为普通对象；这也会造成商品列表消失。后端稳定排序只能处理分页换位，不能修复这个前端类型错误。

现统一使用 `cart.items[0].quantity`、`cart.items[0].image` 等原生数组索引路径，失效商品组同样修复；继续按字段局部更新，不整页重载。查找商品、图片失败处理、数量响应应用和结算入口增加数组校验；已损坏数据提示刷新并暂停结算，刷新后重新读取真实购物车。

此前测试替身仅按点号拆分路径，错误地接受了数组数字点路径。现在支持方括号路径，并明确拒绝对数组使用点号下标，避免测试继续掩盖同类错误。修改测试替身后，旧实现有 5 项购物车测试失败；修正代码后，27 项购物车测试全部通过。新增回归覆盖两个可购商品连续加减、两组图片失败占位、失效项字段更新和异常数组刷新恢复。

本轮 `npm test`：126 项通过，1 项因 Windows 符号链接权限跳过；`npm run check` 和 `npm run check:wechat` 通过。尚未在微信模拟器或真机中复验交互。使用微信开发者工具重新编译小程序并重新进入购物车，可清除旧页面内存中的错误对象；无需清除登录信息或购物车数据。

## 2026-11-17：数量步进器与稳定更新

数量加减改为圆角线框图标，按钮保留 44px 触控范围，中间数量使用等宽数字。达到最小数量或库存上限时只将图标弱化，不让整个列表操作按钮一起变色。

此前加减复用了通用写入流程：写入后重新拉取购物车，期间显示顶部同步提示；服务端按更新时间排序，又会把正在编辑的商品移到列表开头。这些变化会让卡片和滚动位置看起来闪动。现在数量 PUT 成功后直接使用其返回的服务端数据，只通过字段路径更新当前页的数量、小计及真实汇总金额，保持商品顺序、卡片和图片节点。更新期间不显示顶部提示，不全页置灰；结算仍锁定，防止重复提交。接口失败或商品可购状态变化时仍会同步购物车并阻止旧数据结算。

新增购物车回归用例覆盖重复点击、服务端排序、分页、图片失败占位、商品失效、网络失败、账号切换及页面卸载。全量小程序测试 124 项通过、1 项因 Windows 符号链接权限跳过；项目检查和微信原生 WXML/WXSS 编译检查通过。Edge 浏览器示例预览在 320、375、414px 的 24 种状态下通过布局检查，并确认数量更新前后卡片、步进器和结算栏几何位置一致。浏览器结果不替代微信开发者工具和真机检查。

预览位置：[更新中的购物车截图](../artifacts/cart-footer-preview/updating-375.png)、[375px 正常状态](../artifacts/cart-footer-preview/ready-375.png)，或打开[独立示例预览](../artifacts/cart-footer-preview/updating.html)。重新生成和检查运行 `node artifacts/cart-footer-preview/render.cjs`、`node artifacts/cart-footer-preview/check-layout.cjs`。

## 2026-11-17：结算栏进一步优化

本轮重点修改 `pages/cart/index.wxml`、`index.wxss`、`index.js` 及 `tests/cart.test.cjs`：

- 结算栏固定“全选 / 件数与合计 / 去结算”三个区域，按钮固定宽度且不再随件数变化。件数放在合计上方；价格超过 10 个字符时单独排一行，不挤压按钮、不截断金额。数量步进器统一成完整浅色控件。
- 全选支持未选、部分选择、全部选择三种视觉状态。正常结算按钮使用青蓝色、48px 高度和圆角；不可结算时用明确灰色，同时显示当前原因。
- 未勾选、数量输入中、同步失败、失效商品被选中和金额缺失都有就近提示。同步失败/金额缺失可在结算栏刷新，失效商品可“取消勾选”：只取消已选失效项，不删除商品、不更改有效商品的选择。
- 数量输入获取焦点后暂停结算，确认/失焦后再核对金额；前往确认订单期间显示“正在前往”并锁定按钮，即使导航 complete 已回调也不重复打开订单页；打开失败就地提示并恢复操作，回到购物车重新读取服务端状态。
- 使用原生 tabBar 的页面视口，结算栏不额外累加底部安全区域，避免在原生导航之上形成重复留白；内容预留 184px 底部空间，覆盖提示展开和大额金额的较高布局。实际安全区域和键盘行为仍需微信真机验收。

## 设计取舍

日常选购保留勾选、查看商品、调整数量和结算。批量删除、清空购物车放进“管理”，单件移除和批量清理都需要确认。管理模式使用原购物车勾选状态，页面和确认框明确说明删除已选覆盖全部分页，不暗示只删除当前页。

结算栏固定在内容视口底部，页面预留底部空间，原生 tabBar 及其安全区域继续由微信管理。合计只显示服务端 `selectedAmount`，件数来自 `selectedQuantity`，不在前端重新计算价格。标明运费及其他费用以结算页为准；不承诺免运费、包安装或库存预留。缺少价格时显示待确认并暂停结算。

商品图使用 1:1 容器和 aspectFit，避免变形和裁掉关键内容；图片延迟加载，缺失或失败显示规整占位。失效商品单独分组，展示实际库存不足、下架或信息暂不可用提示，不计入商品合计。历史失效勾选未取消时禁用结算，可单独取消或通过全选可购商品清除。

当前购物车数据模型只有商品 ID，没有 SKU/规格快照。页面不编造规格或默认气源，也没有扩大为按 SKU 购买改造；该能力仍依赖原有商品/购物车后端后续补齐。

## 数据与异常处理

- 保留每页 20 种可购商品的上一页/下一页机制，切页时不把旧页伪装成新页。删除后页码超界时返回有效页。
- 同一身份、同一页的并行读取合并。普通刷新期间保留当前卡片；刷新失败保留内容但将其标记为待同步，禁止选择、数量修改、删除及结算，成功重试后恢复。
- 数量仅允许 1 至 min(999, 当前可用库存) 的整数；输入期间暂停结算，失焦或键盘确认后提交；非法输入恢复服务端原数量。数量提交仍携带既有 Idempotency-Key，并重新读取当前页及真实汇总。
- 数量、选择或删除操作后读取服务端状态；提交超时不盲目重放。若无法核对结果，保持待同步并提供重试。
- 账号切换、登录过期时清除原购物车和汇总，旧响应不会覆盖新账号；删除确认期间也核对身份。页面卸载后不再处理迟到响应。
- 全选沿用 `PUT /cart/selection`；既有后端会原子处理所有可购商品并取消失效选择，取消前端逐失效项的额外请求。批量清理沿用 `DELETE /cart/items`，每批最多 100 个，继续发送前核对身份。
- 点击结算进入原 `pages/checkout/index`，下单价格、库存、地址、配送和费用仍由原结算流程向后端校验。

## 运行、预览与人工验收

在微信开发者工具导入 `miniprogram/`，启动原后端并配置 `config.js` 中可访问的 API 地址；编译后点击底部“购物车”，或将编译启动页设为 `pages/cart/index`。

1. 游客：不请求私有购物车；登录入口可用，“先去选购商品”进入分类，登录成功可回到购物车。
2. 有效账号：从商品详情加入商品，核对图片、长标题、单价、小计、件数、服务端合计；逐项勾选与全选后检查汇总。
3. 数量：输入空值、0、小数、超库存数，检查恢复原值；测试减到 1、加到库存上限、手输数量、键盘确认和快速重复点击。
4. 管理：取消与确认单件删除、删除已选、清理失效及清空；超 20 种商品时确认选择和汇总覆盖全部分页，删除最后一页后能返回有效页。
5. 异常：停止后端刷新，卡片保留、结算禁用；恢复后重试。测试图片 404、库存不足/下架、历史失效勾选、过期会话和切换账号。
6. 在 320、375、414px 宽度及带安全区域的机型检查标题两行、方形图片、数量按钮、键盘展开、固定结算栏和原生 tabBar；长列表可滚动到末尾且不被结算栏遮挡。随后在微信真机连接实际后端验收。

在 `miniprogram/` 执行：

```powershell
npm run check
npm test
npm run check:wechat
```

实际自动验证：静态检查通过；微信原生编译器通过 15 个 WXML 页面和 8 个 WXSS 文件；全量 121 项测试，120 通过、1 项原有图片服务符号链接测试因 Windows 权限跳过；购物车测试 21 项全部通过。

当前未运行开发者工具 GUI、真实账号接口联调和微信真机；本次浏览器示例排版截图见上方，仍无微信实际页面截图。上述启动页和步骤是微信可复现预览路径。编译、模拟接口测试和浏览器排版检查不等同于微信键盘或真机视觉验收。

## 后续接入边界

本轮使用原接口，无新接口待接入或演示数据。真实登录、商品、库存及结算依赖原后端；配送、安装及其他费用沿用商家真实配置。购物车规格/SKU 快照和按 SKU 修改需要后端支持，本轮未实现该能力。服务端目前会返回全部失效项；客户端图片已延迟加载，失效项很多时的独立分页仍需后端扩展。
