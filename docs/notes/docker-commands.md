结合你之前处理镜像拉取和容器的场景，Docker 常用命令可以按操作对象分为几类。核心思路是：**镜像（Image）是模板，容器（Container）是运行实例**，日常操作基本围绕这两者展开。

### 镜像管理

镜像操作是容器运行的前提，最常用的是拉取、查看和删除。

*   **拉取镜像**：`docker pull <镜像名>:<标签>`。例如 `docker pull nginx:latest`。如果不指定标签，默认是 `latest`。
*   **查看本地镜像**：`docker images`。加 `-a` 显示所有（含中间层），`-q` 只显示 ID。
*   **删除镜像**：`docker rmi <镜像名/ID>`。如果镜像正在被容器使用，需要先删除容器，或者用 `-f` 强制删除。
*   **构建镜像**：`docker build -t <名称:标签> <Dockerfile所在路径>`。这是从 Dockerfile 创建自定义镜像的标准方式。

### 容器生命周期

这是日常使用最频繁的部分，涉及创建、启停和删除。

*   **运行容器**：`docker run [选项] <镜像>`。常用选项包括：
    *   `-d`：后台运行。
    *   `-it`：交互式终端（常用于进入 shell）。
    *   `--name <名称>`：给容器起个名字，方便后续操作。
    *   `-p <宿主机端口>:<容器端口>`：端口映射，例如 `-p 8080:80`。
    *   `-v <宿主机路径>:<容器路径>`：挂载目录，用于持久化数据或同步代码。
*   **查看容器**：`docker ps` 查看运行中的容器；`docker ps -a` 查看所有容器（含已停止的）。
*   **启停与删除**：`docker start/stop/restart <容器名>` 用于控制状态；`docker rm <容器名>` 删除已停止的容器，加 `-f` 可强制删除运行中的容器。

### 容器调试与交互

容器跑起来之后，排查问题或执行命令主要靠这几个。

*   **进入容器**：`docker exec -it <容器名> /bin/bash`（或 `/bin/sh`）。这是**推荐**方式，它会在容器内新开一个进程，退出终端不会导致容器停止。
*   **查看日志**：`docker logs <容器名>`。加 `-f` 实时跟踪日志输出，`--tail N` 只看最后 N 行，排查报错时非常有用。
*   **查看资源占用**：`docker stats`。实时显示容器的 CPU、内存、网络 IO 等使用情况，类似 Linux 的 `top`。
*   **文件拷贝**：`docker cp <宿主机路径> <容器名>:<容器路径>`，反向操作亦然。用于在不进入容器的情况下复制配置文件或提取日志。

### 系统与清理

*   **查看磁盘占用**：`docker system df`。快速了解镜像、容器、数据卷占用了多少空间。
*   **清理无用资源**：`docker system prune`。删除所有已停止的容器、未被使用的网络和悬空镜像。**注意**，如果加 `-a` 会连未被容器引用的镜像也删掉，执行前需确认。

### Compose 常用命令（针对你的项目）

你之前用的 `docker compose` 是管理多容器应用的工具，和单容器命令略有不同。

*   **启动**：`docker compose up -d`。根据 `docker-compose.yml` 创建并后台启动所有服务。
*   **停止并清理**：`docker compose down`。停止并删除容器、网络（默认不删数据卷）。
*   **查看日志**：`docker compose logs -f <服务名>`。实时查看特定服务的日志。
