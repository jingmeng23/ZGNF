# Java 新手阅读指南

这份文档帮助你按一个真实请求的执行顺序阅读代码。项目使用 Java 25、Spring Boot 3.5 和 Maven；注释解释的是当前代码实际做的事情。

## 先认识几个常见名词

- **Controller（控制器）**：HTTP 接口入口，读取请求、调用 Service，并把结果转换为 JSON。
- **Service（服务）**：放业务规则的层。接口定义可用操作，`impl` 子目录放具体实现。
- **Mapper（映射器）**：数据库访问入口。继承 MyBatis-Plus 的 `BaseMapper` 后，可以使用常见的增删改查方法。
- **Entity（实体）**：数据库记录在 Java 中的对象。字段通常映射到表列。
- **DTO（数据传输对象）**：接口接收的数据。它可以用校验注解拒绝格式错误的请求。
- **VO（视图对象）**：接口返回给客户端的数据形状。
- **Bean（容器对象）**：交给 Spring 创建和管理的 Java 对象。`@Component`、`@Service`、`@RestController` 等注解会让 Spring 发现类。
- **依赖注入**：类通过构造方法声明自己需要的对象，Spring 自动提供它们；例如 Controller 需要 AuthService。
- **Record（记录类）**：适合装载数据的不可变类型。`request.phone()` 是读取 record 组件的访问方式。

## 跟着短信登录走一遍

可以按以下文件顺序阅读：

1. [AuthController.java](../src/main/java/com/gas/ecommerce/modules/auth/controller/AuthController.java) 定义 `POST /api/v1/auth/sms-code` 和 `POST /api/v1/auth/login`。`@RequestBody` 把 JSON 转成 Java 对象，`@Valid` 会触发参数校验。
2. [SmsCodeRequest.java](../src/main/java/com/gas/ecommerce/modules/auth/dto/SmsCodeRequest.java) 使用 `record` 表示手机号请求，并用 `@NotBlank`、`@Pattern` 检查手机号格式。
3. [AuthServiceImpl.java](../src/main/java/com/gas/ecommerce/modules/auth/service/impl/AuthServiceImpl.java) 执行验证码限流、验证码缓存、消息入队、验证码核对、用户创建和 JWT 签发。
4. [EncryptUtils.java](../src/main/java/com/gas/ecommerce/common/utils/EncryptUtils.java) 提供手机号 AES 加密和 HMAC 指纹方法。数据库/缓存查询使用指纹，需恢复手机号时才使用密文解密。
5. [UserMapper.java](../src/main/java/com/gas/ecommerce/modules/user/mapper/UserMapper.java) 是用户数据库访问接口，MyBatis-Plus 根据 Mapper 和实体生成常用 SQL。
6. [JwtTokenProvider.java](../src/main/java/com/gas/ecommerce/common/security/JwtTokenProvider.java) 创建签名令牌。Access token 用于访问 API；refresh token 目前只签发，刷新接口尚未实现。JWT 是签名而非加密，不能把秘密数据放进令牌内容。
7. [Result.java](../src/main/java/com/gas/ecommerce/common/result/Result.java) 将业务返回值包在统一的 `code/message/data/timestamp/traceId` JSON 结构中。

发送验证码成功代表消息已交给 RabbitMQ，不代表短信已经送达。项目当前还没有实现调用短信服务商的消息消费者。

## 带令牌访问接口

1. 客户端把登录响应中的 access token 放在请求头：`Authorization: Bearer <令牌>`。
2. [JwtAuthenticationFilter.java](../src/main/java/com/gas/ecommerce/common/security/JwtAuthenticationFilter.java) 验证令牌，并将用户 ID 和角色写入 Spring Security 的 `SecurityContext`。
3. [SecurityConfig.java](../src/main/java/com/gas/ecommerce/config/SecurityConfig.java) 判断路径是否公开、是否需要登录，以及管理端是否有管理员角色。
4. Controller 可通过 [SecurityUtils.java](../src/main/java/com/gas/ecommerce/common/security/SecurityUtils.java) 读取当前登录用户 ID。

JWT 过滤器只接受 access token；refresh token 不能直接作为 API 登录凭证。无效令牌不会建立登录身份，访问受保护接口时最终会得到 HTTP 401。

## 统一错误和请求追踪

- [GlobalExceptionHandler.java](../src/main/java/com/gas/ecommerce/common/exception/GlobalExceptionHandler.java) 把业务异常、参数错误、权限错误和未预期异常转换成统一响应。
- [TraceIdFilter.java](../src/main/java/com/gas/ecommerce/common/interceptor/TraceIdFilter.java) 在安全检查前生成请求 ID，放进日志 MDC，并通过 `X-Request-Id` 响应头返回。
- 日志里的 traceId 可以帮助把同一个请求产生的多条日志关联起来。MDC 在请求结束时会清除，避免服务器复用线程时串号。

## 数据库与通用 CRUD

- [BaseEntity.java](../src/main/java/com/gas/ecommerce/common/entity/BaseEntity.java) 提供主键、创建时间、更新时间和软删除字段。
- [MyBatisPlusConfig.java](../src/main/java/com/gas/ecommerce/config/MyBatisPlusConfig.java) 注册分页、乐观锁和自动填充插件。
- `Mapper` 继承 `BaseMapper<Entity>` 后，Service 实现类继承 `ServiceImpl<Mapper, Entity>` 可直接使用 `getById`、`save`、`updateById` 等通用操作。
- 这些通用方法不会自动替代完整业务规则。例如下单仍需自行实现库存检查、事务、金额计算和订单状态变更。
- 金额字段使用 `BigDecimal`；时间字段使用 `LocalDateTime`；Long ID 的 JSON 字符串化用于避免 JavaScript 数字精度丢失。

## 怎么看一个 Java 类

1. 看 `package`，确认类属于哪个模块和层。
2. 看类上方的注释和注解。注解通常是给 Spring 或 MyBatis 等框架读取的配置。
3. 看字段，了解类依赖了什么对象或保存了什么数据。
4. 从公开方法开始读。遇到 `this.service` 一类调用时，再跟到对应实现类。
5. 遇到 `@Bean`、`@Service`、`@Mapper` 等注解时，可以理解为告诉框架“这里有一个需要管理的组件”。

## 当前实现范围

认证接口有具体实现；用户资料、商品、购物车、订单、支付、售后、工单、库存和系统管理模块目前主要是分层骨架和 MyBatis-Plus 通用 CRUD。很多 Controller 还没有具体的 `@GetMapping` 或 `@PostMapping` 业务方法。RabbitMQ 中也有需要后续补充的短信消费者和支付通知处理逻辑。

建议先读认证模块和统一响应，再选择一个业务模块补充完整的 DTO 校验、Controller 端点、Service 业务规则、Mapper 查询和测试。
