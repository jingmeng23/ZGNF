# 库存管理与前后端对接

## 必需功能与本次实现

| 功能 | 实现 |
| --- | --- |
| 库存台账 | 商品、实物数量、锁定数量、可用数量；分页、商品名搜索、低库存筛选 |
| 初始建档 | 选择真实商品；同商品禁止重复建档 |
| 入库 | 记录收货数量、操作备注和操作者 |
| 出库 | 仅允许扣减可用库存，保护订单锁定数量 |
| 库存盘点 | 输入盘点后实物总量，系统记录差异；不能低于订单锁定量 |
| 低库存提示 | 可用库存不超过 10 时标记；可输入查询上限，0 表示查找无可用库存的档案 |
| 库存流水 | 初始建档、入库、出库、盘点、订单锁定/释放/扣减；展示数量和锁定前后快照、操作者、请求编号、订单编号、备注 |
| 订单联动 | 复用现有下单锁定、取消释放、履约扣减流程 |
| 一致性与权限 | 复用行锁、事务、数量边界检查、操作者+请求编号幂等；服务端校验 inventory:read / inventory:write |

## 前端入口与数据流

库存管理入口：`/#/admin/inventory`。侧边栏和商品管理页均可进入。

页面 `frontend/src/admin/AdminInventory.vue` 通过 `frontend/src/api/inventory.ts` 调用真实后端接口。
所有请求使用现有 `http.ts`，沿用登录令牌、统一错误处理与请求追踪编号，不使用演示数据。
入库、出库和盘点打开时会重新查询库存详情；提交成功后刷新库存与流水。
页面禁止重复点击提交；同一表单的重试沿用 requestId，由后端防止重复执行。

库存概览中的“本页可用库存”和“本页低库存”仅统计当前页，明确区分分页总数。
“流水”操作会自动按当前库存档案筛选，且支持返回全部流水。
历史流水缺少快照时显示“—”，不会推算历史库存。

## 接口

沿用 [库存 API](../api/inventory-api.md) 的列表、详情、建档、入库、出库、盘点和流水接口。
新增 `GET /api/v1/admin/inventory/options`，需要 `inventory:read`，返回：

```json
{
  "code": 200,
  "data": {
    "products": [{ "id": "123", "name": "燃气灶" }]
  }
}
```

选项只包含未删除商品，不要求额外的商品查询权限。
Long ID 全程使用字符串。
库存审计沿用 V1.9；V1.28 移除位置字段并保留库存行与订单预占关系。

## 本地启动

项目根目录启动基础服务和后端：

```shell
docker compose up -d mysql redis rabbitmq
mvn spring-boot:run
```

在 `frontend` 目录启动前端：

```shell
npm install
npm run dev
```

开发页面默认通过 Vite 的 `/api` 代理连接 `http://localhost:8081`。
不同后端地址可配置 `VITE_API_PROXY_TARGET`；部署到独立站点时可配置 `VITE_API_BASE_URL` 或提供 `/api` 反向代理。
启用登录模式时，使用已分配库存权限的管理员账户。项目现有全局免登录测试配置保持不变。

## 验证

- 前端：`npm run build`、`npm test`。
- 库存后端回归：`mvn "-Dtest=AdminCatalogIntegrationTests#inventory*" test`。
- 后端测试使用 H2 MySQL 兼容模式，覆盖 HTTP 请求、权限、选项筛选、数量保护、审计、幂等、并发和订单联动；不代表真实 MySQL 部署验收。

采购单、仓间调拨、批次/有效期和审批工作流属于后续按业务需求扩展的功能，本次不引入新的单据和仓库模型。
