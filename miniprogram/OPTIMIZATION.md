# 商城小程序优化

## 已完成

- 首页按品牌、搜索、紧凑主题横幅、两列推荐商品和配套服务入口排列。按最新要求移除“食品、生活用品、电子产品”等首页分类栏及燃气/生活切换；商品更靠前。横幅读取现有 `GET /api/v1/mall/home` 运营配置；无有效素材或图片失败时显示品牌渐变背景，不使用外链装饰图片。
- 首页和商城列表使用 `GET /api/v1/mall/search`，首页综合排序、最多读取 6 件真实商品，不加类别或“燃气”关键词限制；商城每页 12 件。首页不再请求分类接口。分类页继续使用 `GET /api/v1/categories/tree` 提供分类、品牌、价格、库存筛选和分页。
- 底部“商城”改为“分类”。首页搜索与“全部商品”、默认横幅通过现有全局页面状态进入商城。搜索框可正常聚焦输入，仅点击搜索或键盘搜索时跳转。从首页进入商城会重置旧品牌、价格、库存等筛选，避免“全部商品”仍被上次条件限制。
- 商品图片使用等比例容器、失败占位和缺货状态。单 SKU/无 SKU 商品可从首页加购，沿用登录和幂等键；多 SKU 商品进入详情选择规格。
- 详情页读取现有 `GET /api/v1/mall/products/{id}` SKU 矩阵并显示规格可售状态。后端购物车目前没有 SKU 字段，多 SKU 商品因此不能进入购物车，避免把未选规格按 SPU 下单。
- 配色统一到品牌深绿 `#163F35`、青蓝 `#087F95`、价格色 `#B54728`、背景 `#F5F7F4`。没有新增依赖。
- 首页增加骨架加载、下拉刷新、空数据与失败重试；刷新失败保留已读商品，横幅失败不影响商品。商品图片 1:1 等比例完整展示、标题最多两行、价格保留两位小数，未知价格不显示为 0。首排图片直接加载，后续图片使用微信懒加载；多规格“选规格”进入详情，单规格仍沿用既有加购与幂等机制。

## 分类模块本轮更新

- 布局调整为固定的搜索、一级分类标签、所选分类下的二级/更深分类、排序栏，下面完整宽度展示双列商品；保留移动端商品图片与文本的阅读空间。原生导航标题改为“商品分类”。分类全部读取真实目录，不硬编码或伪造品类。
- 综合、销量、价格、新品、筛选入口集中一排；价格按钮在升序和降序间切换并明确标示方向。选分类或应用搜索/筛选后回到列表顶部；未提交的搜索词不会混入“加载更多”请求。
- 品牌、价格区间、仅看有货放入底部筛选面板。编辑使用草稿，取消不改变当前查询，重置只清空面板条件，确认时一次应用；校验价格格式及最低价不高于最高价。筛选角标显示实际启用的条件组数。
- 沿用现有分页 API，每页 12 件，滑到底部追加，也可点击“加载更多”。失败保留已加载商品，重试同一页，成功后才推进页码，追加时按商品 ID 去重；相同请求共享结果，过期响应不会覆盖新分类。下拉刷新回到第一页，加载结束后关闭系统提示。
- 首次加载使用骨架占位，分类/品牌加载错误与商品错误分别提示；同条件刷新失败保留已读商品，更换查询后清除旧列表。图片缺失显示占位；图片 1:1 等比例完整展示，长标题两行省略，未知价格不显示 0；后续图片懒加载。
- 商品卡“选购”和“选规格”均进入已有详情页；浏览无需登录。多规格购物车仍受下文所述后端接口限制，本轮没有新增下单、支付或虚构交易能力。

修改文件：`pages/catalog/index.js`（目录层级、筛选草稿、排序、请求及追加分页）、`index.wxml`（页面与底部筛选面板）、`index.wxss`（视觉、安全区域与窄屏样式）、`index.json`（标题、下拉刷新、触底距离）；新增 `tests/catalog.test.cjs`。没有新增依赖、演示数据、后端接口或经营承诺。

接口继续复用 `GET /api/v1/categories/tree`、`GET /api/v1/mall/brands`、`GET /api/v1/mall/search`。查询参数包括 `page`、`size=12`、`keyword`、`categoryId`、`brandId`、`minPrice`、`maxPrice`、`inStock`、`sort`、`order`；商品页继续读取 `results.list/total/pages`，不更改接口契约。分类和商品 ID 全程保留字符串，避免大整数精度丢失；分类归属按父 ID 判断，避免同名分类串入。

实际检查：新增分类测试 14 项全部通过；当前全量共 86 项，85 通过、1 项原有符号链接检查因 Windows 权限跳过。15 页路由、结构、脚本检查通过，微信原生编译接受 15 个 WXML 页面和 6 个 WXSS 文件。自动测试使用模拟接口；没有运行开发者工具 GUI、实际账号联调或真机视觉验收，也没有真实页面截图。

复现预览：在微信开发者工具导入 `miniprogram/` 并重新编译，点击底部“分类”，或使用启动路径 `pages/catalog/index`。建议在 320、375、414px 宽度及底部安全区域机型检查固定栏、双列卡片、长分类名和筛选面板；逐一验证一级/子分类、综合/销量/两种价格方向/新品、筛选取消/重置/确认、空结果恢复、下拉刷新、触底加载和分页失败重试。从首页搜索进入本页应保留搜索词，“全部商品”应清除旧筛选。目录数据不足或没有多页数据时，先用商家真实商品补齐，再进行真实接口验收。

## 当前真实数据

此前检查服务时，可见一级分类为食品、生活用品、电子产品，在售商品为手机、唯怡豆奶和百事可乐，尚未配置燃气商品。此次首页改为展示搜索接口实际返回的可见商品，避免固定专区没有对应商品造成首页空白；不会将其他商品伪装成燃气设备。首页移除分类展示不会删除数据库分类或商品。本轮无新增演示数据或新接口，实际商品以当前后端数据为准。

首页服务入口打开已有 `/pages/services/index`。服务预约 API 已存在，但预约地区、可承接时间、收费及商品订单关联安装能力不能从当前代码确认。首页不承诺服务范围、免费安装或现场费用。

## 多规格购物车接口契约

已有详情读取接口为 `GET /api/v1/mall/products/{productId}/skus?selection=<JSON>`，返回规格维度、选项、SKU ID、SKU 价格与可售库存。当前 `POST /api/v1/cart/items` 请求只有 `{ productId, quantity }`；购物车及结算按商品 ID 处理，不保存或校验 SKU。要开放多规格下单，后端需要将 `skuId` 加入加购 DTO、购物车行、库存/价格读取、购物车返回体、结算预览、订单行快照和幂等键请求摘要；以 SKU 为库存扣减单位并在预览、提交及支付前重新校验。迁移与接口完成后，移除详情页多 SKU 下单限制并添加覆盖 SKU 切换、库存不足、价格变化、重复加购及支付取消的集成测试。

配送运费由现有结算预览返回，用户可看到商品金额、优惠、运费与应付金额。系统没有可确认的安装费用、配送安装限制字段或安装工单订单外键，不应在前端臆造；确定政策并扩展后端字段、迁移和管理配置后，再接入结算和订单详情。
