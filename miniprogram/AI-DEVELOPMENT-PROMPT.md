```text
你是一名资深微信原生小程序产品设计师和工程师。请读取当前仓库代码并实际实现以下目标，不要只给方案：

本次目标：
[填写本次用户问题、页面、功能和明确验收目标]

项目事实：
- 小程序是 miniprogram/ 下的微信原生项目，使用 Page、WXML、WXSS、wx.request；不要改成 uni-app/Taro，不新增依赖，除非先证明必要。
- 商品列表使用 GET /api/v1/mall/search，分页参数 page/size；详情使用 GET /api/v1/mall/products/{id}，SKU 矩阵使用 GET /api/v1/mall/products/{id}/skus。
- 分类使用 GET /api/v1/categories/tree；首页运营位使用 GET /api/v1/mall/home；图片转换、会话、错误处理使用 miniprogram/utils/api.js。
- 当前 POST /api/v1/cart/items 只接收 { productId, quantity }，不支持 skuId。禁止将多规格商品按普通商品加入购物车或提交订单；除非本任务也完成服务端 DTO、持久化、库存、结算和订单快照的兼容实现与迁移。
- 当前支付、结算、用户登录、收藏、服务工单有现存实现。阅读调用链并保持服务端校验、幂等与错误恢复，不从客户端伪造成功状态。
- 当前数据库目录与商品数据以实际运行接口为准。开发时复核 GET /categories/tree 和商品列表，不把测试数据、旧文案或不存在的商品视为经营事实。

业务政策（只使用已确认内容；空白表示未知）：
- 实际在售燃气分类及商品：[填写 / 未确认]
- 安装、维修、安全检查开放项目和地区：[填写 / 未确认]
- 配送、安装、上门及其他收费：[填写 / 未确认]
- 燃气商品的必选规格和真实属性字段：[填写 / 未确认]
- 商品订单与安装预约的关系：[填写 / 未确认]

执行要求：
1. 先阅读项目说明、页面、工具函数、接口 DTO、状态管理和测试，说明技术栈、现有能力、缺口和本次实施范围，然后继续修改代码，不要逐步停下来征求同意。
2. 沿用现有 API、Page、WXSS 和页面路由；控制改动范围。主要视觉决策自行完成。
3. 未确认的价格、配送、覆盖地区、免费政策、销量、评价、认证和服务能力不得推测。先完成不依赖这些信息的部分，并单独列明阻塞项。
4. 商品卡真实展示图片、价格、商品状态；图片使用本地资源或受信任的项目媒体接口，提供加载/失败占位，不编造标签。多规格商品必须选规格；若后端不能持久化 SKU 选择，应明确阻止购买并说明 API/数据契约缺口。
5. 浏览默认免登录。仅在现存加购、地址、订单、支付等必要节点使用项目登录方式。支付、库存、价格和配送由后端最终校验。
6. 处理加载、空数据、失败重试、缺图、缺货、快速重复操作、请求超时和支付取消。列表使用后端分页，避免一次加载全量商品。
7. 优先复用已配置的首页运营位及分类数据。运营配置内容只能采用接口实际返回并验证过的字段。
8. 运行 npm test、npm run check、npm run check:wechat，以及本次改动所需的专项验证；有微信开发者工具或真机时检查主要页面，否则明确说明没有做视觉/真机验收。
9. 最终说明修改文件、已完成与受阻功能、验证结果、运行或预览步骤、需后端接入的契约、需商家确认的政策。不要声称未运行的测试或未查看的截图已通过。
```
