# “我的”页面优化

## 实际修改

- `pages/account/index.wxml`：紧凑头像/昵称区，点击进入个人资料；游客点击登录。订单提前，四个状态入口与“全部订单”集中展示。收藏、浏览记录、优惠券、积分以四列入口展示；地址、服务预约、反馈使用整行入口。账户设置默认收起，展开后提供资料、密码、隐私、登录记录、微信绑定及退出。员工入口移至底部。
- `pages/account/index.wxss`：独立页面样式，深绿、浅绿与白色卡片；16px 参考边距、12px 参考圆角，整行触控区域。沿用原生导航栏适配微信胶囊，页面底部预留安全区域。长昵称省略，窄屏自然滚动。
- `pages/account/index.js`：复用现有消费者登录、资料、订单及服务路由。资料读取失败保留同一账号上次内容并允许重试；加载中不切回游客；重复读取合并；切换账号、登录过期或退出时清除原账号内容，忽略过时请求。退出登录增加二次确认及重复点击保护；员工身份保持独立。
- `assets/account/*.png`：13 个包内透明图标，共约 20 KB，无外链；头像加载失败使用本地图标。`scripts/generate-account-icons.ps1` 保留生成源，可在 Windows PowerShell 执行重新生成，无新增依赖。
- `tests/account.test.cjs`：11 项行为与资源检查，覆盖游客、入口映射、异常重试、请求去重、跨账号响应、退出取消/确认及重复操作。

## 设计与数据约束

用户先看订单，再找常用工具，最后处理低频设置。资料区整体可点击，列表整行可点击，避免只点小箭头。退出放在设置内并要求确认，减少误触。

`paid` 是已付款，`processing` 包含配送或服务处理，因此展示“已付款”“进行中”，不推断物流已发货或安装已完成。实际订单状态及售后继续由原页面提供。积分仅在 `GET /api/v1/users/me` 确实返回时显示，不生成默认积分、会员权益或订单角标；本轮没有新增演示数据、后端接口或服务承诺。

## 可复现预览与验收

1. 在微信开发者工具导入本目录，使用项目已有 AppID 与 `config.js` 后端地址；编译后点底部“我的”，或自定义编译路径 `pages/account/index`。
2. 游客状态：页面展示登录入口，浏览本页不强制登录；点个人资料、订单或常用工具进入现有登录页；员工工作台仍走独立员工登录。
3. 用真实消费者账号登录：检查昵称、头像及实际积分；依次进入四个订单状态、全部订单、四个常用工具、地址、服务预约和反馈。订单入口分别对应 `pending_payment`、`paid`、`processing`、售后页面。
4. 展开账户设置检查资料、密码、隐私、登录记录、微信绑定。测试退出取消后保留账号，确认后显示游客；重新登录另一账号不显示上一账号资料。
5. 停止后端模拟网络失败：同一账号保留已读资料并显示重试；恢复后端点击重试更新。头像失效时应显示本地头像。连续点击入口不重复压入页面。
6. 在 320、375、414px 宽模拟器和有底部安全区域的机型查看：文本不遮挡，图标不缺失，卡片不横向溢出，展开设置可滚动到底部。再进行微信真机检查。

自动验证命令（在本目录执行）：`npm test`、`npm run check`、`npm run check:wechat`。

本次全量测试 63 项：62 通过，1 项原有符号链接检查因 Windows 权限跳过；15 个页面的路由、结构、脚本检查通过；微信原生编译器接受 15 个 WXML 页面和 6 个 WXSS 文件。新增个人中心测试 11 项全部通过。当前没有运行开发者工具 GUI、真实账号接口联调或微信真机，因此没有实际页面截图，也不将编译通过视为视觉或真机验收通过。

本轮功能均接入现有接口，无新增接口待接入。订单数量角标需要后端提供真实汇总后再添加；当前不为角标批量拉取订单。具体预约能力、收费与服务地区继续由原服务模块及商家配置决定。
